# 137. 現有データ範囲と候補キューの不整合監査

監査日: **2026-09-17 JST**  
対象: 現在方針、225Labo限定スコープ、候補C01〜C05、実行設定、直近のC02〜C05成果物

## 結論

直近の停止は、225Labo価格データが一律に利用不能だからではない。**現有225Laboデータで研究すると定めたOHLC限定スコープと、外部入力又は未確認の出来高意味を必要とする候補を同じ自動キューへ載せたこと**が主因である。

さらに、実データPnLを停止するグローバル設定とgrant 0件を維持したまま、候補の入力監査だけを連続実行した。そのため、入力監査は正しくfail-closedになった一方、現有OHLCで実現可能な研究へ移る経路は作られなかった。

これは市場データの欠陥ではなく、候補選定・入力範囲・実行許可を分離し切れていない運用上の不整合である。この不整合を修復する前に、候補数を0として自動終了させるタスクを登録・実行してはならない。

|候補|直近の停止|現有OHLC研究の対象か|今後の扱い|
|---|---|---|---|

| C02 | 出来高列の意味が未確認 | 対象外 | 提供者仕様又は入力範囲の明示的拡張があるまで自動キューに入れない。 |

| C04 | 実発表時刻・DST/JST・OSE対応が未確認 | 対象外 | 価値を含まない公式時刻台帳と、イベント入力範囲の明示的拡張があるまで自動キューに入れない。 |
| C05/R103 | 既存仕様のwarm-up年が4件で下限8件 | 対象内だが旧仕様は閉鎖済み | 旧gateを下げず、次の新規仕様ではwarm-up部分期と必要精度をS0で決める。 |

## なぜ自動化が停止を増幅したか

1. 候補表[124](124_next_research_orchestrator_handoff.md)は、C02〜C04を「入力拡張時」又は「予備候補」と記録していた。
2. 後続のdesignバッチは、この前提を実行可能性の選別条件にせず、各候補の入力監査を既定キューへ登録した。
3. 各監査は、実データ又は必要な一次資料を読まずに不確実性を解消するよう求められたため、必然的に`NOT_VERIFIED`又は`NOT_USABLE`となった。
4. 同時に、現有OHLCだけで可能な新規仕様を選ぶ入口、及びその有限枠・grantを作る入口は停止したままだった。
5. この結果を「候補0」と固定する自動終了タスクを作ると、範囲不整合を研究全体の終了と誤認する危険がある。

## 実施した修正

2026-09-17に、次の規則を`POLICY-20260917-01`として実装した。実行契約は[138](138_current_ohlc_candidate_admission.md)と`config/orchestration/current_ohlc_candidate_admission.json`、コントローラ検査は`orchestrator_batch.py`を正本とする。

1. **候補登録前の入力適格性検査**: `CURRENT_225LABO_OHLC`、`REQUIRES_VOLUME_SEMANTICS`、`REQUIRES_EXTERNAL_SERIES`、`REQUIRES_EVENT_TIMESTAMP_LEDGER`を区別する。自動キューには最初だけ`CURRENT_225LABO_OHLC`を登録する。
2. **候補キューと入力拡張キューを分離する**: 対象外入力の監査完了は、現有データ研究の停止や新family許可を意味しない。
3. **S0で可用性を先に固定する**: warm-up部分期、共同セル、最小効果、精度を、価格PnLを見る前に現有OHLCの非PnL可用性で校正する。既知の4対8、41対45を再計測するタスクは作らない。
4. **実行許可を候補選定に接続する**: OHLC-onlyの一つの完全仕様、閉鎖familyとの関係、有限枠、manifest、ReviewReceipt、grantを一つの再開パッケージとして作る。`market_execution_enabled=false`を単独で解除しない。
5. **自動キュー終了を既定にしない**: `NO_ADMISSIBLE_CANDIDATE`は候補入場判定の有限探索結果だけに使い、入力意味の不足や研究全体の終了には昇格しない。

## 現在必要な決定

次の既定タスクは、新規OHLC-only familyの候補を最大1件に限定して入場判定する。`ADMISSIBLE_FOR_S0`が出た場合だけ、利用者がS0登録パッケージを確認する。`NO_ADMISSIBLE_CANDIDATE`なら、別名による近縁再試行をせず、新しい経済仮説を人手で決める。

- **新規OHLC-only family**: 既存13群との近縁性を事前に照合し、有限枠・S0可用性・完全仕様を新規に定める。
- **閉鎖済みfamilyの例外再レビュー**: 新しい直接根拠、有限枠、完全仕様、ReviewReceipt、grantを揃える。旧仕様の件数gateや時刻を結果後に緩めない。

どちらも外部価格、出来高、経済イベント値を必要としない範囲に限定できる。S0の登録がレビューされるまで、実行設定の停止とOOS・Final Holdoutの保護を維持する。
