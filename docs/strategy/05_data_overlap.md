# D001: 年次ファイル境界での同一バー重複

2026-09-13、戦略PnLの初回計算前に検出。DevelopmentのGoldは1,358,628行、うち5,197時刻が2重に存在した。年次ファイル間で初年営業日のナイトなどが重複する。時刻、trade_date、session、OHLCV、適格性、品質フラグを含むBar全列が一致し、相違するグループは0件だった。

基盤は単一ファイル取り込み時に品質検査するが、複数年の結合時にはsource_file/source_row_numberが異なる同一時刻を残す。生データやGoldを修正せず、研究ローダーで全Bar列が完全一致する重複だけを1バーにまとめる。相違があれば読み込みを拒否する。元の行数、集約件数、source_file別の重複件数を各実験の品質報告に保存する。欠損バー補完や価格変更ではない。

再現・回帰検証: 合成の同一Barを異なるsource_fileとして与え、1バー化と品質件数を確認。価格が異なる場合は失敗する。2026年とforwardの不正Parquet sentinelが読み込まれないことも検証。

初回キャンペーンは読み込み時に中止し、取引/PnLは未計算。既存の基盤結果は変更しない。研究エンジン本体の修正はない。この処理方針をR001の実行前データ規約として追加した。
