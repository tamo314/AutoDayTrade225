## 実施する作業

1. **会計訂正**：旧designの121行付近の式はgross_fillからスリッページを再控除している。13の `gross_fill = reference_gross - slippage_attribution`、`net = gross_fill - fees`（他費用がある場合は明示控除）に揃え、訂正理由と合成例を残す。1枚、倍率100円、tick=5ポイント、片道1tick＋30円を維持する。
2. **工程別の要件**：カレンダー整理・合成検証には資本/DD値や閉鎖family再開を一律要求しない。実データ診断、PnL、OOS・運用の各要件を分離する。最小効果・必要精度・必要件数は研究上の設計方法と根拠を具体化し、未指定の運用値を架空の値で埋めない。現在の作業に不要な未決値を停止理由にしない。
3. **機構調査**：祝日取引制度の存在は既知情報。現物再開時の価格形成、先物で既に情報が反映されるという反論、継続と反転の代替説明を一次資料・原著で調べる。日本市場への直接証拠と他市場からの間接証拠を分け、検索語・未取得資料・試した代替取得方法を残す。論文の存在や有意な予測力を捏造しない。支持論文なしでも、必要な調査を行った根拠と仮説の限界を整理できれば当該調査は完了可能。
4. **公式カレンダー**：2021-01-01～2025-06-30の全calendar_dateについて現物開場、OSE祝日取引、OSE trade_dateを公式の過去資料で対応付け、出典・公開時点・制度境界・版を保存する。現在の制度を過去全期間へ当てはめず、価格バーの存在から推測しない。カレンダーだけの日数集計は許可するが、価格由来の件数診断は行わない。将来バー・取引価格・volumeにアクセスしない。
5. **一つの設計の整合化**：対象は現物休場中にOSE祝日取引がある場合の再開後の初動継続。祝日＋週末を含む休場がtreatmentと除外群の両方にならないよう、優先規則と反例を明示する。修正は理由付きのPnL未評価設計変更として記録する。窓・方向・コストを変えた戦略候補の追加、C02以降への切替、好成績による選択はしない。
6. **検証の実行と修正**：固定validatorを実行し、失敗は根本原因を修正して再実行する。文書・出典・計算単位・時点利用可能性もレビューする。JSONの構造PASSだけを市場事実や経済性のPASSにしない。

## Planner／Executorの判断

実行設定の6完了条件すべてに証拠があり、機械検証と最終監査が通った場合だけdoneとする。HOLD/REJECTという研究判断だけでは完了しない。未完了の資料整理、矛盾、式の誤り、テスト失敗はcontinueで修正タスクを渡す。

blockedは、許可範囲を越えなければ得られない必須情報、複数の取得・代替方法を試しても回収不能な必須公式資料、権限・資源の障害、矛盾した必須要件などに限定する。障害の証拠、試した対処、未完了範囲を明示する。「資本DD未指定」「今回はHOLD」「ファイルを作成した」は、それだけではblocked/doneの根拠にならない。

市場データ・OOS・Final Holdout・R065 payload、売買エンジン・閉鎖台帳・grant・制御コード・固定validatorは今回変更/アクセスしない。公開制度・カレンダーと合成例の範囲で自主的に作業し、通常の調査・訂正ごとにユーザーへ確認を返さない。
